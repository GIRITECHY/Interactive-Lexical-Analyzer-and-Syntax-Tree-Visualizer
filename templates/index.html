LexiTree – Language Guide & Viva Reference

1. Formal Grammar Specification

program     -> statement*
statement   -> IDENTIFIER "=" expression ";"
expression  -> term (("+" | "-") term)*
term        -> unary (("*" | "/") unary)*
unary       -> ("+" | "-") unary | primary
primary     -> NUMBER | IDENTIFIER | "(" expression ")"

2. Operator Precedence & Associativity

Precedence Operator Description Associativity
1 (Highest) ( ... ) Parentheses Non-associative
2 +, - Unary Plus & Minus Right-to-Left (Prefix)
3 *, / Multiplication & Division Left-to-Right
4 (Lowest) +, - Addition & Subtraction Left-to-Right

3. Compiler Design Viva Questions & Answers

Q1: What is the difference between a Lexical Analyzer and a Syntax Analyzer?

Ans: The Lexical Analyzer (Lexer) converts the stream of input characters into meaningful units called Tokens, discarding whitespace and flagging illegal characters. The Syntax Analyzer (Parser) takes this token stream and verifies that it adheres to the formal context-free grammar, constructing an Abstract Syntax Tree (AST).

Q2: Why use a Recursive-Descent Parser?

Ans: A Recursive-Descent Parser is a top-down parsing technique where each non-terminal in the grammar is implemented as a function. It is intuitive, easy to debug, supports unambiguous operator precedence, and gives precise syntax error diagnostics.

Q3: What is the difference between a Parse Tree and an Abstract Syntax Tree (AST)?

Ans: A Parse Tree (Concrete Syntax Tree) contains all syntactic details including punctuation and parentheses. An AST retains only the structural, semantic information needed for translation (operators, operands, identifiers) without syntactic noise like semicolons or parentheses.
